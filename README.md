# TikTok Live Aff — ระบบจัดการไลฟ์ & คิดเงินพนักงาน

ระบบจัดการงาน **TikTok Live Affiliate** สำหรับทีมที่ไลฟ์ขายของหลายช่อง
ใช้บันทึกยอดขายรายวันต่อช่อง ติดตาม KPI/เป้าหมายทีม และ **คิดเงินพนักงานอัตโนมัติ**
ทำงานทั้งหมดในเบราว์เซอร์ — ข้อมูลเก็บใน `localStorage` ของเครื่องคุณ ไม่ส่งขึ้นเซิร์ฟเวอร์

## ฟีเจอร์

- **ภาพรวม (Dashboard)** — การ์ดสรุป (ยอดขาย/รับจริง/ค่าแอด/ROAS/ช่องที่ใช้งาน),
  กราฟเปรียบเทียบยอดขายรายช่อง, สถานะบัญชีทุกช่อง และ **ตารางอันดับช่อง**
  (ยอดขาย · ค่าแอด · ค่าคอมฐาน · รับจริง · ROAS)
- **Realtime Live** — สรุปยอดขาย "วันนี้" รายช่องแบบเรียลไทม์
- **ช่อง TikTok** — ทะเบียนช่อง เพิ่ม/แก้/ลบ, สถานะ (ใช้งาน/พัก/ปิด), ผู้ดูแล, ทีม
- **บันทึกยอดขาย** — ลงยอดขายรายวันต่อช่อง (ยอดขาย, ค่าแอด, ค่าคอมฐาน, รับจริง)
- **พนักงาน & KPI** — ทะเบียนพนักงาน + ตั้งค่าค่าตอบแทน (ฐาน + คอมมิชชั่น) และเป้า KPI
  พร้อมแถบความคืบหน้า KPI ต่อคน
- **ทีม & เป้าหมาย** — จัดกลุ่มทีม, ตั้งเป้ายอดขายรวม, ติดตาม % ความคืบหน้าเทียบเป้า
- **บันทึกงานรายวัน + คิดเงินพนักงาน** — ลงเวลาทำงาน/กะรายวัน แล้ว
  **สรุปคิดเงินพนักงานอัตโนมัติ** ต่อเดือน พร้อมส่งออก CSV
- **คัดสินค้ายิงแอด (Shopee → Facebook Ads)** — นำเข้าสินค้าจาก Shopee แล้วให้คะแนน
  ทุกตัวจาก 6 ปัจจัย ตัดเกรด A/B/C/D บอกว่า "ตัวไหนคุ้มที่จะจ่ายค่าแอดไปหาคนซื้อ"
  พร้อมมุมโฆษณา/ประโยคเปิดคลิป/งบทดสอบ และส่งออก shortlist เป็น CSV
- **ตั้งค่าระบบ** — ชื่อกิจการ, คอมมิชชั่นเริ่มต้น, สำรอง/กู้คืน (JSON), ข้อมูลตัวอย่าง, ล้างข้อมูล

## วิธีคิดเงินพนักงาน

ยอดรับจริงต่อเดือนของพนักงานแต่ละคน คำนวณอัตโนมัติจาก:

```
รวมรับ = ค่าจ้างฐาน + คอมมิชชั่น + โบนัส KPI + ปรับเพิ่ม/หัก
```

- **ค่าจ้างฐาน** — เลือกได้ต่อคน: เงินเดือน (จ่ายเต็มต่อเดือน) หรือ รายวัน (× จำนวนวันทำงาน
  ที่นับจากเมนู “บันทึกงานรายวัน”, ไม่รวมวันที่ทำเครื่องหมาย “ขาด”)
- **คอมมิชชั่น** — คิดจากยอดขายของพนักงาน ตั้งได้ 2 แบบ
  - *อัตราเดียว* — เช่น 3% ของยอดขายทั้งหมด
  - *ขั้นบันได (progressive)* — เช่น ยอด 0–100,000 คิด 3%, ส่วนที่เกิน 100,000 คิด 5%
    (แต่ละขั้นคิด % เฉพาะส่วนของยอดที่อยู่ในช่วงนั้น)
- **โบนัส KPI** — จ่ายเมื่อยอดขายถึงเป้า KPI ที่ตั้งไว้
- **ปรับเพิ่ม/หัก** — ใส่ค่าบวกเพื่อเพิ่ม หรือค่าลบเพื่อหัก (เช่น เบี้ยขยัน / ค่าปรับ)

พนักงานที่ไม่ได้ตั้งคอมมิชชั่นเอง จะใช้ **คอมมิชชั่นเริ่มต้น** จากหน้า “ตั้งค่าระบบ”

## เริ่มใช้งาน

```bash
npm install
npm run dev      # เปิด http://localhost:5173
```

คำสั่งอื่น:

```bash
npm run build    # สร้างไฟล์ production ในโฟลเดอร์ dist/
npm run preview  # พรีวิว build

```

> เปิดครั้งแรกให้ไปที่ **ตั้งค่าระบบ → โหลดข้อมูลตัวอย่าง** เพื่อดูภาพรวมการทำงานทั้งหมด

## โหมดข้อมูล: เก็บในเครื่อง vs. ฐานข้อมูลกลาง (หลายคน/หลายเครื่อง)

แอปทำงานได้ **2 โหมด** โดยอัตโนมัติ ขึ้นกับว่าตั้งค่า Supabase ไว้หรือไม่:

| | **โหมดเครื่อง** (ค่าเริ่มต้น) | **โหมดคลาวด์** (ตั้งค่า Supabase) |
|---|---|---|
| ที่เก็บข้อมูล | `localStorage` ในเบราว์เซอร์ | ฐานข้อมูลกลาง (Supabase Postgres) |
| ใช้หลายเครื่อง/หลายคน | ❌ ต่างเครื่องเห็นคนละชุด | ✅ ทุกเครื่องเห็นชุดเดียวกัน sync ทันที |
| ล็อกอิน | ไม่มี | มี (อีเมล/รหัสผ่าน) |
| ต้องตั้งค่าเพิ่ม | ไม่ต้อง | ตั้งค่า Supabase (ดูด้านล่าง) |

> ถ้า **ไม่ใส่** ค่า env ของ Supabase แอปจะเป็นโหมดเครื่องเหมือนเดิมทุกประการ

### ตั้งค่าโหมดคลาวด์ด้วย Supabase (ฟรี)

1. สมัคร **[supabase.com](https://supabase.com)** → **New project** (ตั้งรหัสผ่าน DB, เลือก region ใกล้ไทย เช่น Singapore)
2. เปิด **SQL Editor** → วางไฟล์ [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์ → **Run**
   (สร้างตาราง + เปิดสิทธิ์เฉพาะผู้ล็อกอิน + เปิด realtime)
3. ไป **Project Settings → API** คัดลอก **Project URL** และ **anon public key**
4. ตั้งเป็น environment variables:
   - ตอนพัฒนา: คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่า
   - ตอน deploy บน **Vercel**: **Settings → Environment Variables** เพิ่ม
     `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY` แล้ว **Redeploy**
5. สร้างบัญชีผู้ใช้: เปิดเว็บ → หน้า **เข้าสู่ระบบ** → "สร้างบัญชีพนักงานใหม่"
   (หรือสร้างในหน้า Supabase → Authentication → Users)
   - แนะนำ: Supabase → Authentication → Providers → ปิด "Confirm email" เพื่อให้ล็อกอินได้ทันที

เสร็จแล้วทุกคนที่ล็อกอินจะเห็น/แก้ข้อมูลชุดกลางร่วมกัน และอัปเดตสด ๆ ข้ามเครื่อง

## Deploy ออนไลน์ (ฟรี)

แอปเป็นเว็บ static จึง deploy ฟรีได้ทันที มีไฟล์ config ให้แล้ว (`vercel.json`, `netlify.toml`)

## คัดสินค้า Shopee ไปยิงแอด Facebook

เมนู **“คัดสินค้ายิงแอด”** ตอบคำถามเดียว: *ดีลนี้คุ้มที่จะจ่ายค่าโฆษณาไปหาคนซื้อไหม*
ไม่ใช่ *ลดเยอะไหม* — ของลด 80% ราคา ฿15 ลดแรงมากแต่ได้ค่าคอมไม่ถึงบาท

### เกณฑ์ให้คะแนน (เต็ม 100)

| ปัจจัย | คะแนน | เหตุผล |
| --- | ---: | --- |
| ส่วนลด | 30 | ตัวหยุดนิ้วคนดู เริ่มนับที่ 30% เต็มที่ 70% ขึ้นไป |
| ช่วงราคา | 25 | ฿300–999 ได้เต็ม เพราะคอมคุ้มค่าคลิกและตัดสินใจไว |
| จำนวนรอบที่ขึ้น | 15 | ขึ้นหลายรอบ = คลิปตัวเดียวยิงได้หลายวัน ต้นทุนต่อออเดอร์ถูกลง |
| หมวดหมู่ | 12 | ของใช้ในบ้าน เครื่องใช้ไฟฟ้า ความงาม สัตว์เลี้ยง มาก่อนเสื้อผ้าที่ยกเลิกสูง |
| รอบเที่ยงคืน | 10 | มีรอบ 00:00 ได้เปรียบ เพราะออเดอร์เข้าหนาที่สุดชั่วโมงแรก |
| คอมต่อชิ้น | 8 | ประเมินที่ 5% ถ้าต่ำกว่า ฿7 ต่อออเดอร์แทบไม่เหลือกำไร |

แล้วหักคะแนนเพิ่มเมื่อเจอสัญญาณเสี่ยง (เรตติ้งต่ำกว่า 4.0, รีวิวน้อยกว่า 5 ชิ้น,
ไม่มีราคา/ส่วนลด, ยังไม่มียอดขาย) ก่อนตัดเกรด:

| เกรด | คะแนน | ความหมาย |
| --- | ---: | --- |
| A | 75+ | ยิงได้เลย |
| B | 60–74 | น่าสนใจ ทดสอบงบเล็กก่อน |
| C | 40–59 | เฝ้าดู ใช้เสริมในคลิปรวมดีล |
| D | ต่ำกว่า 40 | ข้าม |

น้ำหนักและเกณฑ์ทุกตัวปรับได้จากแท็บ **“เกณฑ์ให้คะแนน”** (บันทึกไปกับ settings)

### เอาข้อมูลสินค้าเข้าระบบ 3 ทาง

1. **นำเข้าไฟล์** — CSV / TSV / XLSX / JSON กดปุ่ม “นำเข้าไฟล์สินค้า”
   ระบบอ่านหัวคอลัมน์ทั้งไทยและอังกฤษให้เอง ดูตัวอย่างคอลัมน์ที่
   [`docs/shopee-template.csv`](docs/shopee-template.csv)
   ถ้าไฟล์มี 1 แถวต่อ 1 รอบดีล ระบบจะรวมรอบของสินค้าตัวเดียวกันให้อัตโนมัติ
2. **ดึงผ่าน Shopee Affiliate Open API** — ต้องมีบัญชี affiliate ที่เปิด Open API แล้ว

   ```bash
   export SHOPEE_APP_ID=xxxx
   export SHOPEE_APP_SECRET=xxxx
   npm run fetch:shopee -- --pages 20 --keyword "หม้อทอด" --out shopee-products.json
   ```

   แล้วนำไฟล์ JSON ที่ได้เข้าระบบผ่านปุ่มนำเข้า
   (Shopee ไม่เปิดให้ไล่ดูสินค้าทั้งหมดของทุกร้านรวดเดียว — ดึงเป็นรอบตามคำค้น/หมวด
   แล้วสะสมไว้ ระบบจะรวมตัวซ้ำจาก `shopId + itemId` ให้เอง)
3. **ข้อมูลตัวอย่าง** — กดปุ่ม “ข้อมูลตัวอย่าง” เพื่อลองระบบก่อนมีไฟล์จริง

### AI วิเคราะห์

- **ไม่ใส่คีย์ก็ใช้ได้** — ระบบวิเคราะห์ด้วยกฎในเครื่อง บอกจุดแข็ง/ความเสี่ยง
  มุมโฆษณา ประโยคเปิดคลิป กลุ่มเป้าหมาย งบทดสอบต่อวัน และจุดคุ้มทุน
  (ต้องปิดการขายกี่ % ต่อคลิกถึงจะไม่ขาดทุน คิดจาก CPC ที่ตั้งไว้)
- **ใส่คีย์** (ปุ่ม “ตั้งค่า AI”) เพื่อให้โมเดลช่วยเขียนมุมโฆษณา/แคปชั่นเพิ่ม
  รองรับบริการที่ใช้รูปแบบ OpenAI (ตั้ง Base URL เองได้)
  **API key เก็บใน `localStorage` ของเครื่องนั้นเท่านั้น ไม่ถูกซิงก์ขึ้นฐานข้อมูลกลาง**

### ส่งออกไปทำแอด

ปุ่ม **“ส่งออก CSV”** จะได้ shortlist ตามเงื่อนไขที่กรองไว้ (เกรด, หมวด, ส่วนลดขั้นต่ำ,
ราคาไม่เกิน, เฉพาะรอบเที่ยงคืน) พร้อมคะแนน เกรด คอมต่อชิ้น และลิงก์สินค้า
