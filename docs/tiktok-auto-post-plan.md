# แผนระบบโพสต์คลิป TikTok ปักตะกร้าอัตโนมัติ

> เอกสารวางแผน (ยังไม่เขียนโค้ด) — ฉบับสำหรับผู้ที่ตอนนี้มี **บัญชี TikTok ปกติ** และ
> อยากทำระบบโพสต์คลิปพร้อมผูกสินค้า (ปักตะกร้า) แบบอัตโนมัติจำนวนมาก
>
> อัปเดต: 2026-08-17

---

## 0. สรุปสั้น (อ่านอันนี้ก่อน)

**เป้าหมายที่อยากได้:** โพสต์คลิป TikTok พร้อมปักตะกร้า อัตโนมัติ ทีละหลายร้อยคลิป

**ความจริงที่ต้องรับก่อน:**

| ความเชื่อ | ความจริง |
|---|---|
| "ยิงรัว 100+ คลิปทีเดียว" | เป็นรูปแบบ **spam** ที่ TikTok ตรวจจับและแบนโดยตรง — ทำแล้วเสียบัญชี ไม่คุ้ม |
| "บัญชีปกติก็ยิง API โพสต์ได้" | **ไม่ได้** ต้องมี Developer App ที่ผ่าน audit ก่อน |
| "ปักตะกร้าผ่านโปรแกรมได้เลย" | **ไม่ได้** ต้องเป็น TikTok Shop Seller หรือ Affiliate Creator ที่เชื่อมร้านแล้ว |
| "ใช้บอทกดหน้าจอ/เบราว์เซอร์แทนคน" | ผิด ToS ตรงๆ เป็นสาเหตุอันดับ 1 ที่บัญชีขายของโดนแบน — **ไม่แนะนำเด็ดขาด** |

**สิ่งที่สร้างได้จริงและถูกกฎ:** ระบบ **"คิวอัปโหลด + ตั้งเวลาโพสต์กระจาย"** ที่เอาคลิปหลายร้อยไฟล์
เข้าคิว ใส่ข้อมูล (แคปชั่น/แฮชแท็ก/รหัสสินค้า) แล้วให้ระบบ **ทยอยโพสต์ตามตารางที่ปลอดภัย**
ผ่าน **Content Posting API ทางการ** — ไม่ใช่ยิงพร้อมกันทีเดียว

**สิ่งที่ต้องทำก่อนระบบทำงานได้ (บัญชีปกติทำไม่ได้):**
1. สมัคร **TikTok for Developers** และขอ **Content Posting API** (ต้องผ่านการ audit)
2. สมัคร/อัปเกรดเป็น **TikTok Shop Seller หรือ Affiliate Creator** (เงื่อนไขของการปักตะกร้า)

> ถ้ายังไม่พร้อมขอ API → ข้ามไปดู **หัวข้อ 8 (ทางเลือกไม่ต้องเขียนโค้ด)** ได้เลย

## 1. เข้าใจ 3 ระดับของการโพสต์อัตโนมัติ

การ "โพสต์อัตโนมัติ" มี 3 แบบ ต้องแยกให้ออกเพราะความเสี่ยงต่างกันมาก:

### ระดับ A — Official API (แนะนำ ✅)
ใช้ **TikTok Content Posting API** อย่างเป็นทางการ TikTok รับรู้และอนุญาต
- ✅ ปลอดภัยต่อบัญชี ไม่ผิด ToS
- ✅ ทำ automation ได้จริง (คิว/ตั้งเวลา)
- ⚠️ ต้องมี Developer App ที่ผ่าน audit, มี rate limit, ทำตาม UX guideline

### ระดับ B — Browser/Mobile Bot (ห้าม ❌)
ใช้ Selenium / Puppeteer / Appium ปลอมเป็นคนกดโพสต์
- ❌ ผิด ToS ข้อ "automated means / scraping / bot"
- ❌ TikTok มีระบบ device fingerprint + behavior detection จับได้
- ❌ บัญชีขายของโดนแบน = เสียทั้งร้านและ affiliate — **เอกสารนี้จะไม่ออกแบบแนวนี้**

### ระดับ C — Manual-assist (ปลอดภัยสุด แต่ไม่ auto เต็ม)
ใช้ตัวตั้งเวลาในตัวของ TikTok เอง (TikTok Studio scheduler) หรือ partner ที่ได้รับอนุญาต
คนยังเป็นผู้กดยืนยัน แต่ระบบช่วยจัดคิว/เตรียมข้อมูลให้ → ดูหัวข้อ 8

**เอกสารนี้เลือกทำ ระดับ A เป็นหลัก และมี ระดับ C เป็นทางสำรอง**

## 2. ประเมินสถานะปัจจุบัน: "บัญชีปกติ"

ตอนนี้บนบัญชีปกติ **ยังทำสิ่งเหล่านี้ไม่ได้** จนกว่าจะปลดล็อก:

| ต้องการ | ต้องปลดล็อก | วิธี |
|---|---|---|
| โพสต์คลิปผ่านโปรแกรม | Content Posting API + audit | สมัคร TikTok for Developers |
| ปักตะกร้า (ผูกสินค้าในคลิป) | TikTok Shop Seller หรือ Affiliate | สมัครใน TikTok Shop / Seller Center |
| โพสต์แทนบัญชีตัวเองโดยไม่ต้องกดเอง | ผ่าน audit เป็น `video.publish` | ยื่นรีวิว use case กับ TikTok |

> **ก่อน audit ผ่าน:** Developer App จะโพสต์ได้เฉพาะโหมด **SELF_ONLY (คนอื่นมองไม่เห็น)**
> ใช้เทสได้ แต่โพสต์สาธารณะจริงต้องรอผ่านรีวิว

## 3. เส้นทางสู่การทำได้จริง (ถูกกฎ) — ทีละขั้น

### ขั้น A · เปิดสิทธิ์ Content Posting API
1. สมัคร/ล็อกอิน **developers.tiktok.com** ด้วยบัญชีธุรกิจ
2. สร้าง **App** → ขอ product **"Content Posting API"**
3. ขอ scope:
   - `video.upload` — อัปโหลดเข้ากล่องร่าง (draft) ให้เจ้าของกดโพสต์เอง
   - `video.publish` — โพสต์ตรง (Direct Post) *ต้องผ่าน audit*
4. ตั้งค่า **redirect URI** และ (ถ้าใช้ PULL_FROM_URL) **verify โดเมน** ที่จะให้ TikTok ดึงไฟล์
5. ยื่น **audit** พร้อมอธิบาย use case + วิดีโอ demo UX → รอผลอนุมัติ

### ขั้น B · เปิดสิทธิ์ปักตะกร้า (TikTok Shop)
- ต้องเป็นหนึ่งใน:
  - **TikTok Shop Seller** (มีร้านค้าใน Seller Center) หรือ
  - **Affiliate Creator** ที่เชื่อมร้าน/เข้าร่วม affiliate แล้ว
- การผูกสินค้าเข้ากับคลิป (product anchor / showcase) จะทำได้ก็ต่อเมื่อบัญชีมีสิทธิ์นี้
- การผูกสินค้าผ่าน **API** อยู่ใน TikTok Shop Partner/Shop API ซึ่งเปิดให้เฉพาะพาร์ตเนอร์ที่อนุมัติ
  — ช่วงแรกอาจต้อง **ปักตะกร้าด้วยมือในแอป** แล้วให้ระบบเราจัดการแค่ตัวคลิป+แคปชั่น

### ขั้น C · สร้างระบบคิว + ตั้งเวลา (ส่วนที่เราเขียนเอง)
เมื่อได้ token แล้ว ระบบของเราจะทำหน้าที่: จัดคิว → ตั้งเวลา → เรียก API ทยอยโพสต์ →
ติดตามสถานะ → รายงานผล (ดูสถาปัตยกรรมหัวข้อ 4)

## 4. สถาปัตยกรรมระบบที่จะสร้าง

### 4.1 ภาพรวมส่วนประกอบ

```
┌─────────────────────────────────────────────────────────────┐
│  Web UI (ต่อยอดจากแอป TikTok Live Aff เดิม — React)          │
│  • หน้าจัดคิวคลิป  • ตั้งตารางเวลา  • ดูสถานะ/ผลโพสต์        │
└───────────────┬─────────────────────────────────────────────┘
                │
        ┌───────▼────────┐        ┌──────────────────────────┐
        │  Queue Service │◄──────►│  Database                │
        │  (คิว+ตั้งเวลา) │        │  clips / jobs / accounts │
        └───────┬────────┘        │  products / logs         │
                │                 └──────────────────────────┘
        ┌───────▼────────────┐
        │  Scheduler/Worker   │  ← ทำงานตาม cron, เคารพ rate limit
        │  (ทยอยยิงทีละคลิป)  │
        └───────┬─────────────┘
                │  OAuth token ต่อบัญชี
        ┌───────▼──────────────────────────┐
        │  TikTok Content Posting API      │
        │  + (ถ้ามีสิทธิ์) Shop product API │
        └──────────────────────────────────┘
```

### 4.2 Data model (ร่าง)

```
accounts      : id, ชื่อช่อง, tiktok_open_id, access_token, refresh_token,
                token_expire_at, daily_limit, สถานะ warm-up
clips         : id, path/URL, ขนาดไฟล์, ความยาว, สถานะไฟล์, checksum
products      : id, ชื่อสินค้า, tiktok_product_id / affiliate_link
post_jobs     : id, clip_id, account_id, caption, hashtags[], product_ids[],
                visibility, scheduled_at, status(queued|uploading|posted|failed),
                publish_id, error_message, retry_count
post_logs     : id, job_id, ts, event, payload (ไว้ตรวจย้อนหลัง/แก้ปัญหา)
```

### 4.3 Flow การอัปโหลด (Content Posting API)

มี 2 วิธีรับไฟล์ เลือกได้:
- **PULL_FROM_URL** — เราวางไฟล์บนโดเมนที่ verify แล้ว, ส่ง URL ให้ TikTok ไปดึงเอง (ง่ายกว่า)
- **FILE_UPLOAD** — อัปโหลดแบบ chunk ตรงเข้า TikTok (คุมได้มากกว่า)

ลำดับทำงานต่อ 1 คลิป:
1. `POST /v2/post/publish/video/init/` — เปิด session ได้ `publish_id` + upload URL
2. อัปไฟล์ (chunk) **หรือ** ให้ TikTok pull จาก URL
3. แนบ metadata: caption, hashtags, visibility, (ถ้ามีสิทธิ์) product anchor
4. `GET .../status/fetch/` — poll สถานะจน `PUBLISH_COMPLETE` หรือ error
5. บันทึกผลลง `post_logs` และอัปเดต `post_jobs.status`

### 4.4 ตัวจัดคิว + rate limit + กระจายเวลา (หัวใจของ "หลายร้อยคลิป")

แทนที่จะยิง 100 คลิปพร้อมกัน (= โดนแบน) ระบบจะ:
- แตกคิวออกเป็น **jobs ตั้งเวลา** กระจายทั้งวัน/หลายวัน
- ต่อบัญชี: จำกัด **N คลิป/วัน** และเว้นระยะขั้นต่ำระหว่างโพสต์ (เช่น ≥ 20–40 นาที)
- สุ่ม jitter เวลาเล็กน้อยให้ดูเป็นธรรมชาติ (ไม่ใช่ตรงเป๊ะทุกชั่วโมง)
- ถ้ามีหลายช่อง → กระจายโหลดข้ามช่อง (ใช้ registry ช่องจากแอปเดิม)
- Backoff + retry เมื่อ API ตอบ error/limit

### 4.5 การปักตะกร้า (product anchor)
- **ถ้าได้สิทธิ์ Shop API:** เก็บ `tiktok_product_id` ใน `products` แล้วแนบตอนสร้าง job
- **ถ้ายังไม่ได้:** ระบบเตรียมคลิป+แคปชั่นให้ครบ แล้ว "ส่งเข้าร่าง" (`video.upload`)
  ให้คนเปิดแอปกด **เพิ่มสินค้า → โพสต์** เอง (กึ่งอัตโนมัติ — ยังประหยัดเวล่ามาก)

### 4.6 ต่อยอดจากแอปเดิม
แอป `TikTok Live Aff` มีทะเบียนช่องอยู่แล้ว (`src/views/ChannelsView.jsx`) →
ใช้ต่อเป็น registry บัญชีสำหรับผูก token และกระจายคิวได้เลย ไม่ต้องเริ่มใหม่

## 5. ขอบเขตความปลอดภัยบัญชี (สำคัญกว่าความเร็ว)

> ตัวเลขด้านล่างเป็น **แนวทางอนุรักษ์นิยม** เพื่อกันบัญชีโดน flag —
> ต้องเช็ก rate limit ล่าสุดจากเอกสาร Content Posting API ประกอบเสมอ

- **บัญชีใหม่/ยังไม่ warm-up:** เริ่ม 1–3 คลิป/วัน แล้วค่อยเพิ่ม
- **บัญชีที่ active สม่ำเสมอ:** ~10–20 คลิป/วัน ถือว่าปลอดภัย
- **เว้นระยะระหว่างโพสต์:** อย่างน้อย 20–40 นาที + jitter
- **หลายร้อยคลิป** = ต้อง **กระจายหลายวัน และ/หรือ หลายช่อง** ไม่ใช่วันเดียว
- เนื้อหาต้อง **ไม่ซ้ำเป๊ะ** (คลิป/แคปชั่นซ้ำ = โดนลดการมองเห็น)
- คุม token ให้ปลอดภัย (เก็บเข้ารหัส, refresh อัตโนมัติ, ไม่ commit ลง git)

## 6. โรดแมปเป็นเฟส

| เฟส | สิ่งที่ทำ | ผลลัพธ์ |
|---|---|---|
| **0 · เตรียมสิทธิ์** | สมัคร Developer App, ขอ Content Posting API, สมัคร Shop/Affiliate | มี client key/secret + สิทธิ์ปักตะกร้า |
| **1 · Auth** | OAuth flow, เก็บ/refresh token ต่อบัญชี | เชื่อมช่องเข้าระบบได้ |
| **2 · โพสต์เดี่ยว** | อัปโหลด+โพสต์ 1 คลิปผ่าน API (โหมด SELF_ONLY ก่อน) | พิสูจน์ว่ายิงได้จริง |
| **3 · คิว+ตั้งเวลา** | Queue + Scheduler + rate limit + retry | โพสต์หลายคลิปกระจายเวลาได้ |
| **4 · ปักตะกร้า+UI** | แนบสินค้า, หน้าจัดการคิว, รายงานผล, bulk import | ระบบครบตามเป้า (แบบถูกกฎ) |

**เริ่มเฟส 1 ได้ทันที** ที่ผ่านเฟส 0 (มี key จาก TikTok)

---

## 7. สิ่งที่ "ไม่ทำ" และเหตุผล

- ❌ **บอทกดหน้าจอ/เบราว์เซอร์** — ผิด ToS, บัญชีขายของเสี่ยงแบนถาวร
- ❌ **ยิงคลิปพร้อมกันทีเดียวหลายร้อย** — รูปแบบ spam, ถูกตรวจจับ
- ❌ **โพสต์คลิป/แคปชั่นซ้ำจำนวนมาก** — โดน shadowban
- ❌ **ขาย/แชร์ token, ใช้ API ข้ามบัญชีที่ไม่ได้ยินยอม** — ผิดข้อตกลง
- ❌ **หลบการตรวจจับของแพลตฟอร์ม** — ไม่ทำ

---

## 8. ทางเลือกถ้ายังไม่พร้อมขอ API (ทำได้เลยตอนนี้)

ถ้ายังไม่อยากผ่านขั้นตอน audit สามารถใช้ทางถูกกฎเหล่านี้ก่อน:

1. **TikTok Studio Scheduler (ในตัว TikTok เอง)**
   - เข้า tiktok.com บนเดสก์ท็อป → อัปโหลด → **ตั้งเวลาโพสต์ล่วงหน้าได้**
   - ถ้าบัญชีมีสิทธิ์ Shop/Affiliate จะ **ปักตะกร้าในหน้าอัปโหลดได้เลย**
   - ข้อจำกัด: ทำทีละคลิป (ไม่ bulk) แต่ **ปลอดภัย 100% และไม่ต้องเขียนโค้ด**

2. **Partner ที่ TikTok อนุญาต** (เช่นเครื่องมือจัดตารางโซเชียลที่เชื่อม TikTok อย่างเป็นทางการ)
   - จัดคิว/ตั้งเวลาหลายคลิปได้ผ่าน API ที่ได้รับอนุญาต
   - แต่ฟีเจอร์ปักตะกร้ายังขึ้นกับสิทธิ์ Shop ของบัญชี

3. **กึ่งอัตโนมัติด้วยระบบเรา (เฟส 2 แบบ draft)**
   - ระบบเตรียมคลิป+แคปชั่น+แฮชแท็ก แล้วส่งเข้า **กล่องร่าง** ผ่าน `video.upload`
   - คนแค่เปิดแอปกด "เพิ่มสินค้า → โพสต์" — ยังเร็วกว่าทำมือทั้งหมดมาก

---

## 9. ขั้นถัดไปที่แนะนำ

1. ตัดสินใจว่าจะเดินเส้น **Official API (เฟส 0)** หรือเริ่มจาก **ทางเลือกหัวข้อ 8** ก่อน
2. ถ้าเลือก Official API → เริ่มสมัคร Developer App และ Shop/Affiliate (ผมช่วยร่างเอกสารยื่น audit + use case ได้)
3. เมื่อได้ key แล้ว → ผมเริ่มเขียนโค้ดเฟส 1 (OAuth) ต่อจากแอปเดิมได้ทันที

> เอกสารนี้เป็น **แผน** ยังไม่มีการเขียนโค้ดระบบโพสต์ บอกได้เลยว่าจะให้เดินเฟสไหนก่อน
