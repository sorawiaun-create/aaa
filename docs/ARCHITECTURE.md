# สถาปัตยกรรมระบบ AI ผลิตคอนเทนต์แบบหลายแผนก (ฉบับเต็ม)

ระบบนี้จำลอง "เอเจนซี่ผลิตคอนเทนต์" ทั้งทีมด้วย AI แบ่งเป็นหลายแผนก
แต่ละแผนกเป็น AI agent เฉพาะทาง มี "ผู้จัดการ" (Orchestrator) คอยแตกงานและสั่งงานให้อัตโนมัติ
**และมีเลเยอร์ผลิตสื่อ + บันทึกไฟล์จริง + หน้าพรีวิว**

## ภาพรวม

```
                        โจทย์จากลูกค้า/แบรนด์
                                │
                                ▼
                 ┌──────────────────────────────┐
                 │   ผู้จัดการฝ่ายผลิตคอนเทนต์      │
                 │        (Orchestrator)         │
                 │  วางแผน → แตกงาน → มอบหมาย     │
                 │  → รวบรวม → สรุปส่งลูกค้า        │
                 └──────────────┬───────────────┘
                                │  มอบหมายงาน (tool use)
   ┌──────┬──────┬──────┬──────┼──────┬──────┬──────┬──────┐
   ▼      ▼      ▼      ▼      ▼      ▼      ▼      ▼      ▼
 กลยุทธ์  เทรนด์  เขียนบท วิดีโอ  ภาพ  อินฟลูฯ ยิงแอด จัดโพสต์  ตรวจ
                        │      │                    │       แบรนด์
                        ▼      ▼                    ▼
                  ┌───────────────────────────────────────┐
                  │  เลเยอร์ผลิตสื่อ + บันทึกไฟล์            │
                  │  (providers/media.js, output.js)      │
                  │  → assets/*.svg, video-brief.md,      │
                  │     post-<platform>.md, index.html     │
                  └───────────────────────────────────────┘
```

## แต่ละแผนกทำอะไร

| แผนก | หน้าที่ | ผลลัพธ์ / ไฟล์ที่สร้าง |
|------|---------|------------------------|
| **วางแผนกลยุทธ์** | แปลงโจทย์เป็นแผน | Big Idea, Content Pillars, รายการชิ้นงาน |
| **วิจัยเทรนด์ & แฮชแท็ก** | มุมมาแรง + แท็ก | ฟอร์แมตยอดนิยม, คีย์เวิร์ด, แฮชแท็กแยกแพลตฟอร์ม |
| **เขียนบท & แคปชั่น** | hook/สคริปต์/แคปชั่น | บทวิดีโอ, ข้อความโพสต์, CTA |
| **วิดีโอ** 🛠️ | สตอรี่บอร์ด + เรนเดอร์ | `assets/*.md` (render brief) — ต่อ text-to-video |
| **ภาพ & กราฟิก** 🛠️ | ทิศทางภาพ + สร้างภาพ | `assets/*.svg` (หรือ .png เมื่อต่อ API) |
| **อินฟลูเอนเซอร์** | เลือก KOL + บรีฟ | แผน KOL, บรีฟ, วิธีวัดผล |
| **ยิงแอด (Paid Media)** | โครงสร้างแคมเปญโฆษณา | targeting, ad copy A/B, ตัวชี้วัด |
| **จัดโพสต์ตามแพลตฟอร์ม** 🛠️ | โพสต์พร้อมเผยแพร่ | `post-<platform>.md` แต่ละแพลตฟอร์ม |
| **ตรวจแบรนด์ & คุณภาพ** | ตรวจก่อนปล่อย | ✅ ผ่าน / ⚠️ แก้ก่อนปล่อย |

🛠️ = แผนกที่มี **tools** ของตัวเองเพื่อสร้างไฟล์จริง

## กลไกการทำงาน (2 ชั้นของ tool use)

**ชั้นที่ 1 — ผู้จัดการมอบหมายแผนก**
- ผู้จัดการมี tool `delegate_to_<แผนก>` (สร้างอัตโนมัติจากทะเบียนแผนก)
- ตัดสินใจเองว่าจะเรียกแผนกไหน ตามลำดับใด (ไม่ hardcode) และส่งผลแผนกก่อนหน้าเป็นบริบทของแผนกถัดไป

**ชั้นที่ 2 — แผนกเรียก tool สร้างไฟล์**
- แผนกที่มี `tools` (วิดีโอ/ภาพ/จัดโพสต์) จะรัน inner agentic loop เรียก tool อย่าง
  `generate_image`, `generate_video`, `save_post` เพื่อสร้างไฟล์จริงลงโฟลเดอร์แคมเปญ

**เลเยอร์ผลิตสื่อ (`providers/media.js`)**
- โหมด `placeholder`: สร้างไฟล์ตัวอย่างจริง (SVG แสดง prompt/บรีฟ) → pipeline ครบวงจรทันทีโดยไม่ต้องมี key
- ต่อ API จริง (text-to-image / text-to-video) ได้ที่จุด `TODO` จุดเดียว

**เลเยอร์ output (`output.js`)**
- สร้างโฟลเดอร์ `output/<campaign>/`, บันทึกผลแต่ละแผนกเป็น `NN-<key>.md`
- รวมทุกอย่างเป็นหน้าพรีวิว `index.html` (แสดงภาพ, ลิงก์ไฟล์, สรุป)

## ลำดับข้อมูล (Data Flow)

```
brief ──▶ orchestrator(loop)
             │  delegate_to_strategy   ─▶ dept(strategy)  ─▶ 01-strategy.md
             │  delegate_to_trend      ─▶ dept(trend)     ─▶ 02-trend.md
             │  delegate_to_copywriting─▶ dept(copywrite) ─▶ 03-copywriting.md
             │  delegate_to_visual     ─▶ dept(visual) ─tool▶ assets/*.svg + 04-visual.md
             │  delegate_to_video      ─▶ dept(video)  ─tool▶ assets/*brief.md + 05-video.md
             │  delegate_to_platform   ─▶ dept(platform)─tool▶ post-*.md + 06-platform.md
             │  delegate_to_brand_qa   ─▶ dept(brand_qa)  ─▶ 07-brand_qa.md
             ▼
      99-final-summary.md + index.html
```

## การต่อยอด

- **สร้างภาพ/วิดีโอจริง**: เติมโค้ดเรียก API ที่จุด `TODO` ใน `src/providers/media.js`
- **โพสต์อัตโนมัติจริง**: ต่อ API แพลตฟอร์ม/เครื่องมือตั้งเวลาโพสต์ ในตัว executor ของ `save_post`
- **ลดต้นทุน**: เปลี่ยนบางแผนกใช้โมเดลเล็กลง ผ่าน `CONFIG.departmentModel`
- **เพิ่มแผนก**: เพิ่ม object (พร้อม `tools` ถ้าต้องสร้างไฟล์) ใน `src/departments/index.js`
- **Human-in-the-loop**: เพิ่มขั้นให้คนอนุมัติก่อนแผนก "จัดโพสต์" ปล่อยงานจริง
- **หน่วยความจำข้ามแคมเปญ**: เก็บ brand guideline/ผลงานเก่าไว้ในไฟล์ แล้วป้อนเป็นบริบท
